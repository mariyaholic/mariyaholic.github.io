Yozora

Yozora is a Windows app. It finds the music or video that plays on your computer and shows it on your Discord profile as Rich Presence. You select which players it can read.

Install Yozora

Caution

The Yozora files do not have a code signature. Windows SmartScreen can show the message “Windows protected your PC”. Compare the checksum before you run the file.

  1. Download Yozora-Setup.exe and SHA256SUMS.txt from the latest release.
  2. In PowerShell, get the checksum of the installer: 
    Get-FileHash .\Yozora-Setup.exe -Algorithm SHA256
  3. Make sure that the value is the same as the value for Yozora-Setup.exe in SHA256SUMS.txt. If the values are different, do not run the file.
  4. Open Yozora-Setup.exe. The installer installs Yozora for your user account only. It does not ask for administrator rights.
  5. If SmartScreen shows a message, select More info, then select Run anyway.
  6. Open Yozora from the Start menu. The control panel opens.

A portable Yozora.exe is also on the release page. The automatic update procedure does not apply to the portable file.

A newer installer over an existing install upgrades in place. Setup stops the running Yozora first, keeps your settings and starts Yozora again if it was running. A fresh install starts nothing on its own. If start at sign-in is on and Yozora now runs from a different folder, Yozora points the sign-in entry at its current location the next time it starts.

Set up the Discord card

Discord desktop must run on the same computer. You do not need a Discord client secret.

  1. Start Discord desktop.
  2. Open the Yozora control panel. The setup checklist shows three checks: Discord found and connected, Media detected and Card visible on Discord.
  3. Play a track in a music player.
  4. Select Send test card. Discord shows the card “Yozora test card” for 15 seconds.
  5. If the card does not show, in Discord go to Settings > Activity Privacy and turn on Share my activity.

When all checks pass, the checklist closes. To show it again, select Show setup checklist in the Diagnostics section. Yozora has its own Discord application ID built in, so nothing needs entering. If Discord refuses the handshake, the checklist shows an application ID field. It accepts 17 to 20 digits. An empty value goes back to Yozora's app.

Select sources and priority

A source is a type of player, for example Spotify or a browser. Yozora shows one source at a time. The source at the top of the priority list wins when it plays.

  1. In the control panel, find the source list.
  2. Select the check box of each source that Yozora can read.
  3. To change the order, drag a source by its grip. Or, select the source grip and push the Up or Down arrow key.
  4. Select Apply.
Note

On a new install, Browser media / videos and Other media players are off. YouTube, Twitch and background browser tabs each have a separate switch. These switches are also off by default.

Yozora reads music through the Windows media controls. For YouTube and Twitch, it can also read the address bar of the active browser tab. This read happens only while a track plays, and Yozora keeps only the video ID or the channel name.

  • YouTube needs Browser media / videos. It matches an exact Edge or Chrome window title. When one window matches, the card shows Watching YouTube with the video thumbnail and a Watch on YouTube button. With YouTube off, matching tracks stay hidden.
  • Twitch works the same way. The card shows the live preview from Twitch and a Watch on Twitch button. An offline channel has no preview. VODs, clips and directory pages have no channel login, so they show no button.
  • Background Edge tabs reads the tab names of up to 8 browser windows and looks for a YouTube tab that plays audio. A tab name alone gives no video address, so it shows no Watch button. With the switch off, matching tracks stay hidden.
Note

Yozora never reads the address bar of an unrelated foreground tab to identify a background video.

If Yozora verified a video address while its tab was active, the same media item keeps its YouTube identity, thumbnail and Watch button when the tab changes. A different media item, a different browser or a long gap drops the kept evidence. Edge must continue to expose the media session. Two videos with identical metadata cannot be told apart by this check.

Browser videos use only the thumbnail the browser supplies through the Windows media controls. Browser titles are never matched against music catalogs. Discord's servers cannot read the local dashboard art cache, so a browser card can appear on Discord without a large image.

The priority list is a total order over the six sources: applemusic, spotify, spotifyapi, youtubemusic, browser and generic. If the top source stops, the next source that is on takes over. The order saves to sources.order in cadence.toml together with the source switches. The panel drops unknown or duplicate entries on load.

The tray menu is built each time it opens. The first row is greyed and names the current track, or says Nothing playing. YouTube, Twitch and Background Edge tabs appear below a separator, checked as saved.

YouTube Music is a dedicated source, on by default, for its browser app and supported desktop apps. It always uses a Listening card with a fixed YouTube Music symbol, without catalog lookups or a listen button. A custom app filter such as msedge still blocks it; its own switch cannot override a filter.

Connect the Spotify Web API

The desktop Spotify app works with no setup. The Spotify Web API source adds exact artwork and track links. You need a free Spotify developer app.

  1. Create an app at the Spotify developer dashboard with the Web API enabled. Add the Redirect URI the panel shows (http://127.0.0.1:<panel port>/spotify/callback). No client secret is needed.
  2. Paste the app's client ID (32 characters, 0-9 and a-f) into the panel and select Connect. Your normal browser opens Spotify's sign-in page.
  3. After you agree, Spotify returns to the panel. Yozora stores the refresh token in Windows Credential Manager and starts at once. A restart is not needed.

The flow is Authorization Code with PKCE (S256). The code verifier stays in memory and expires after 10 minutes. The state value is random, is checked in constant time and works once, so a replayed or forged callback is refused without contacting Spotify. Tokens and codes are never logged or shown. Selecting Disconnect stops the polling, deletes the token and sets spotify.mode back to system.

The panel picks a free port each run. Spotify checks the redirect URI against the ones registered for the app, so set a fixed port in [server] port if you reconnect often. An existing connection keeps working whatever the port.

The terminal setup command also connects Spotify, for scripted installs. It asks for the client ID only, prints the sign-in address and opens it in your browser, and waits on http://127.0.0.1:8977/spotify/callback for up to 10 minutes. Add that exact Redirect URI to your Spotify app first. Earlier versions asked for a client secret and stored it in Credential Manager; nothing reads it now, and a successful setup deletes the old entry. If you connected through the old terminal flow, run setup again to get a working token.

Shape the Discord card

The Discord card section of the panel edits the card settings. Apply changes saves all at once or not at all, Discard changes goes back to what is saved, and Reset to defaults fills the form for you. Yozora picks the change up on its next update.

  • Presets: Default, Compact, Album and Detailed. Load into form previews a preset. Loading does not save; select Apply to keep it.
  • Text lines: the top line, the second line and the two image tooltips are Go templates of at most 256 characters. The panel shows the rendered result and refuses a template that does not run. Placeholders lists what a template can use.
  • Choices: what the card shows while a track is paused (show or hide), the activity type (listening, watching, playing) and the status display (app, state, details).
  • Buttons: the listen-along label (at most 32 characters; empty or Listen along gives the service-specific label) and the search fallback.

The panel saves through /api/card, which rejects unknown fields, out-of-range choices and bad templates without changing the file.

Card text uses the track you play. The header names the player: Listening to Spotify, Listening to Apple Music, or the player's name. Browser sessions name the browser, not a guess at the streaming service in it. Players are matched from a fixed table of Windows app IDs and exe names in the source. Tidal, Deezer, Qobuz, Amazon Music, foobar2000, MusicBee, AIMP, VLC, iTunes, Apple TV, Media Player and Windows Media Player stay under Other media players. An app that is not in the table is also generic and gets a name from its exe or app ID.

Artwork is found asynchronously, so a slow artwork service does not delay the song text. Yozora asks the iTunes Search service first, for the storefront of your Windows region. If iTunes has nothing, it asks Deezer's public search, which needs no key, and uses the image only when the title and the artist both match. Deezer art carries no track link, so it adds no Listen button. Results are cached for a day per storefront. Override the storefront in cadence.toml; it takes effect from the next track:

[art]
  country = "GB"   # ISO 3166 alpha-2 code; empty follows the Windows region

The small image is Yozora's application icon. Override discord.small_image with a Discord asset key or a publicly accessible image URL.

The second card button links to the Yozora repository. The built-in address lives in internal/config/config.go, in Defaults() as Buttons.YozoraURL. To point it somewhere else, set it in %APPDATA%\uika-resonance\cadence.toml:

[buttons]
  enabled = true
  label = "Listen along"
  spotify_search_fallback = true
  yozora_url = "https://github.com/mariyaholic/yozora"

No local drive path or enclosing repository name is used to build the address. A folder move therefore needs no code change.

Hide tracks

Some tracks should never reach your profile, and that is okay. A hidden track is treated like a blocked source: it is never sent to Discord, nothing is looked up for it, and a card already showing for it is cleared at the next rate step. The panel preview still shows it, marked Hidden from Discord.

  1. Select Hide this song (artist and title together) or Hide this artist on the preview.
  2. To remove a rule again, open the Hidden from Discord list in the Discord card section.

Rules live in cadence.toml, one table each. Every named field must match:

[[sources.hidden]]
  artist = "Some Artist"

[[sources.hidden]]
  artist = "Another Artist"
  title = "Song * (Live)"

A field matches the whole value, ignoring case and surrounding spaces. * stands for any run of characters. There is nothing else, so there are no regular expressions. A rule made only of *, or empty, is ignored so it can never hide everything. At most 200 rules, each field at most 128 characters. While a hidden track is playing from the highest-priority source, a lower-priority source is not used instead.

Back up panel settings

Panel settings backup exports the saved card fields, source switches, priority and appearance as yozora-panel-settings.json. Unsaved form edits are not included. Account connections, client IDs, hidden-track rules, startup and system settings are outside the backup. Card text you wrote is included, so review the file before you share it.

  1. To restore, choose a JSON backup of up to 64 KiB and review its values.
  2. Select Apply import. Validation and preview do not save.
  3. If another panel or the tray changed supported settings after the preview, make a fresh preview first.

Invalid hand-edited saved settings return an export error, but a valid backup can still restore supported values.

The panel and the tray menu come in English and Japanese. Follow Windows uses the Windows display language, English and 日本語 fix one. Product and service names stay in Latin script, and the Discord card is not translated: its text comes from your own template settings.

With a Windows contrast theme on, the panel uses the system colours, so nothing depends on the theme's own colours.

Colours are copied from each source palette. Where a colour would fall below 4.5:1 as text, a lighter or darker value is used instead and marked derived in internal/server/ui.html. Each theme's faces ship inside the binary (Latin subsets, about 370 KB, under the SIL Open Font License) and the panel serves them itself, so nothing is fetched from the network. Night sky uses Segoe UI and Confluence uses Georgia and Consolas, which Windows already has. The theme faces cover Latin only, so Japanese text uses Windows' own Yu Gothic UI or Meiryo; Mariyaholic-98 uses MS Gothic for the closest match to its bitmap look.

Pause sharing

A pause removes your Discord card in approximately five seconds. Yozora continues to find media, but it does not send it to Discord.

  • To pause, select Pause sharing for 1 hour or Pause until I resume in the tray menu. Or, select Pause sharing in the control panel.
  • To stop the pause, select Resume sharing.

A pause stays in memory only. When Yozora starts again, the pause stops. While paused, the preview shows “Sharing paused until 15:30” (or “Sharing paused”) with a Resume button.

The panel also offers an interface: POST /api/pause with {"action":"pause","minutes":60} (1 to 1440), {"action":"pause"} (until resumed) or {"action":"resume"}. /api/state reports paused and paused_until.

Update Yozora

Yozora checks GitHub for a new release approximately one time each day. The first check starts about two minutes after launch. A check does not install a release.

  1. To check now, go to the Startup section and select Check for updates.
  2. When a new release is available, select Update now.
  3. Yozora downloads the installer, compares its SHA-256 checksum with SHA256SUMS.txt and installs it. Your settings stay the same.
  4. Open the control panel again from the tray icon.

A check goes to api.github.com with the user agent Yozora/<version> and nothing else about you or your machine. The time and result are remembered in update.json, so a restart does not force another check. A local dev build never checks. To stop all update checks, add this to %APPDATA%\uika-resonance\cadence.toml:

[update]
check = false

Update now downloads only over HTTPS, only from github.com and GitHub's release download hosts, up to 50 MB, and runs the installer silently. Nothing is ever installed unless you press one of these.

Note

An unsigned build checks the checksum only. The checksum comes from the same release as the installer. It finds a damaged download. It does not find a changed release. If this is not sufficient for you, update manually from the release page.

To test the update path from an older build, install the pinned v0.2.1 Setup and follow the rollout guide.

Remove Yozora

  1. Go to Settings > Apps > Installed apps.
  2. Find Yozora and select Uninstall.
  3. The uninstaller asks Also remove my settings and cached data? Select Yes to remove all data. Select No to keep it.

If you select Yes, the uninstaller removes these items:

  • %APPDATA%\uika-resonance (settings)
  • %LOCALAPPDATA%\uika-resonance (artwork cache, logs, status files)
  • %TEMP%\uika-probe
  • The Spotify entries in Windows Credential Manager

A silent uninstall (unins000.exe /VERYSILENT) keeps all of these unless you add /PURGE=1.

The settings file

Settings live in %APPDATA%\uika-resonance\cadence.toml. Each time the file loads or saves cleanly, Yozora keeps a copy beside it as cadence.toml.last-good.

If a hand edit breaks the file while Yozora runs, the change is ignored, the previous settings stay in use, and the log says why. If the file is broken when Yozora starts, Yozora starts with the last good copy and moves your edited file to cadence.toml.broken-YYYYMMDD-HHMMSS so you can fix it. Without a usable last-good copy, startup fails with the parse error.

log.level is read at startup and again at every config reload, so a hand edit or a panel save takes effect without a restart.

Speed

With media playing, Yozora checks the Windows media sessions every sources.poll_ms (default 1000 ms) and updates its state every 250 ms. After a minute with no media session and nothing on your Discord profile, it slows to one session check every 5 seconds and one update every 2 seconds. It returns to full speed as soon as any session appears.

A newly started track shows in Yozora within about 5.25 seconds at worst, and on Discord after the usual presence.track_debounce_ms (default 500 ms) on top. While a card is still on your profile, Yozora stays at full speed so the clear is not delayed. A poll_ms of 5000 or more is left as it is. Discord sends stay at least five seconds apart, so fast detection is not a promise of an immediate Discord-visible update. Artwork can arrive as a later update.

Logs

The background process writes %LOCALAPPDATA%\uika-resonance\logs\uika-resonance.log. Past 5 MB the file is renamed to uika-resonance.log.1 and a new file starts, so the logs never take more than about 10 MB.

[log]
level = "info"   # debug, info, warn, error or off

debug adds the source file and line to each entry and off writes no log file. The log lines carry no severity yet, so warn and error currently write the same lines as info. An unknown value is logged and treated as info.

Copy report under Diagnostics copies a plain-text report for bug reports: version, Windows build, source, artwork route, Discord state, last error, enabled sources and theme. It never contains track titles, artists, tokens, client IDs or file paths with your user name. Save report downloads the same report as yozora-diagnostics.txt. If the browser refuses clipboard access, the text is shown in a box to select by hand.

Recent, just below Diagnostics, lists the last 20 distinct tracks Yozora published this run, newest first, with a thumbnail, title, artist and how long ago. It stays in memory only: nothing is written to disk and it is empty after a restart.

Build from source

Requirements: Windows and Go 1.27.1 or later.

go mod download
go test ./... -count=1
go build -ldflags=-H=windowsgui -o Yozora.exe ./cmd/yozora
./Yozora.exe serve

Yozora.exe without an argument opens the control panel. With an argument, it operates as a command-line tool. One file does both jobs. The control panel starts the background process by re-launching itself with serve. The background process owns the tray icon. Its Open control panel item re-launches the file with the internal panel command. The panel window runs in its own short-lived process. It exits when it closes or when the background process stops.

Commands
CommandFunction
serveStarts the background process and the tray icon.
statusShows the current state.
doctorRuns diagnostic checks.
setupRuns the setup in the terminal, for scripted installs.
install / uninstallTurns start at Windows sign-in on or off.
stopStops a Yozora process that started from the same file.
versionShows the version. A local build shows dev.

The build uses the windowsgui linker flag. A double-click on Yozora.exe opens no console window.

The build stamps the version with -ldflags "-X uika-resonance/internal/version.Version=0.2.N", as the release workflow does. Without this option, version shows dev.

The icon of Yozora.exe comes from cmd/yozora/rsrc_windows_amd64.syso. To generate that file again from assets/yozora.ico, run go-winres simply --arch amd64 --icon ../../assets/yozora.ico --manifest gui.

Limits

  • The regression tests use a private Windows named pipe, not the live Discord client. Ordinary go test ./... never publishes anything to a Discord profile.
  • The browser regression check exercises the panel with synthetic media and settings. It does not exercise native WebView2 or media detection.
  • The Spotify connect flow is tested against a local fake token endpoint. It has not yet been tried against Spotify itself.
  • Native WebView2 download handling still needs a Windows smoke test for the report download in this build.

The browser regression check runs on Linux with Node.js:

npm install --prefix /tmp/yozora-ui-tools --no-save --no-package-lock playwright@1.62.1
/tmp/yozora-ui-tools/node_modules/.bin/playwright install chromium
NODE_PATH=/tmp/yozora-ui-tools/node_modules node scripts/check-ui.cjs

To use an existing Chromium installation, set CHROMIUM_PATH to its executable instead of installing Playwright's browser. Screenshots and results.json are written to the system temporary directory under yozora-ui-check; set UI_EVIDENCE_DIR to choose another location.

Repository and release

A merge to main that changes what ships builds and publishes a release automatically. What ships: Go sources (not _test.go files), go.mod/go.sum, the icon resources, the installer, the embedded panel or the workflow itself. Documentation, scripts and test-only merges do not cut a release. The version is <series>.N: the latest tag of the series plus one, starting at .0 for a new series. The series (0.2 now) is set by hand in the workflow and raised for a big change. Use the “Run workflow” button on the release workflow to republish without a code change.

packaging/winget/ holds manifest templates for package Mariyaholic.Yozora (Inno installer, per-user scope). Each release fills in the version, download URL and installer SHA256 and uploads them as a build artifact. Nothing is sent to winget automatically. To publish, open a pull request to microsoft/winget-pkgs with the three files under manifests/m/Mariyaholic/Yozora/<version>/. Validate locally first with winget validate.
