Sitekit

Sitekit is a build tool. It makes a static room catalogue from data files. It then checks the catalogue in a browser before release.

Runtime
Node.js 22 or later; Python 3.13 or later with Playwright for the browser audit
Status
0.1.0 source preview, no release
Source
mariyaholic/sitekit, commit 13c87e7
License
Apache-2.0

Build a room catalogue

  1. Install Node.js 22 or later and Python 3.13 or later.
  2. Install the Python development requirements into a virtual environment: 
    .venv/bin/pip install -r requirements-dev.txt
  3. Install the Playwright Chromium browser: 
    .venv/bin/python -m playwright install chromium
  4. Run the builder: 
    node build.mjs

The builder writes dist/ from the example catalog examples/room-catalog/catalog.json. The file requirements-dev.txt contains the exact reviewed Python versions.

To run the build and the freshness check together, run ./scripts/build.sh. On Windows, run scripts/build.ps1. The generated dist/ and audit-report.json are local outputs. The repository does not track them.

Check the build

  1. After each edit, run node build.mjs --check. This command verifies the generated output.
  2. Run the browser audit: 
    .venv/bin/python audit.py
  3. Run the test suite: 
    npm test

The audit checks the room and item counts, the navigation, the details interaction, the reduced-motion behaviour, the theme tokens and the horizontal overflow. It checks at narrow and wide viewports.

Note

The builder implements a narrow room-catalogue contract and a limited subset of JSON Schema. Read the contract before you add fields.

The audit fails when the browser is missing. It never passes silently.

Configure the audit

The audit reads the file audit.config.json. Pass the file with --config audit.config.json. CLI flags override the values in the file.

The file sets the audit viewports, the tokens and the paths. The example file sets a narrow and a wide viewport, and the token selectors under --sk-. See docs/CONTRACT.md for details.

Use the catalog contract

The builder validates a catalog against a documented subset of JSON Schema. The subset has six keywords: type, properties, required, items, enum and additionalProperties.

An unsupported keyword in a supported subschema fails the build by default. Without this default, partial validation could look like full JSON Schema support.

A room id maps to a fixed asset path: assets/rooms/<id>.svg.

docs/CONTRACT.md documents the page contract, the ARIA wiring and the audit report shape. ROADMAP.md lists what stays out of scope.

Keep everything local

The builder never uses the network.

The audit starts a loopback HTTP server on 127.0.0.1 with a random port. The server serves the local built site. Playwright drives a local browser. Nothing is uploaded and there is no telemetry.

You install Playwright and its browser one time. This is a developer step.

Limits

Note

Sitekit is a source tool. It is not a general-purpose site generator and not a verified npm release.

Sitekit is in early development with the v1 scope. Sitekit is not affiliated with MetaQuotes. MetaTrader 5 (MT5) is a MetaQuotes trademark, and sitekit contains no MT5 integration.

This project ships source only. It does not ship Windows binaries. Windows binaries, if someone produces them in future, are not code-signed yet. Windows SmartScreen may warn when they are downloaded or run.

The Python requirement files pin the reviewed runtime and test dependencies exactly. See THIRD_PARTY.md for the dependency licence policy and asset provenance. For test guidance, see docs/TESTING.md.
