Ad Astra

Ad Astra is a research program. It analyses astronomical archive data. For each result, it records the source and the evidence level.

Runtime
Python 3.10 or later; hosted runs use 3.12
Status
0.1.0 source preview, no release
Source
mariyaholic/ad_astra, commit 728f327
License
Apache-2.0

Run a campaign

  1. Make a virtual environment and install the campaign extras: 
    python -m venv .venv
.venv/bin/python -m pip install -e ".[test,site,campaign]"
  2. Examine the queue of targets: 
    .venv/bin/python -m cygnus.campaign queue
  3. Select the next target. This command writes the specification file: 
    .venv/bin/python -m cygnus.campaign new --next
  4. Run the campaign. Archive retrieval needs a network connection: 
    .venv/bin/python -m cygnus.campaign run campaigns/<slug>.yaml
  5. Make the report: 
    .venv/bin/python -m cygnus.campaign report campaigns/<slug>.yaml
Note

These commands use the macOS and Linux form. On Windows, replace .venv/bin/python with .venv\Scripts\python.exe.

Note

A run takes 1 to 5 minutes. A run is resumable: run the same command again after a failure.

The full procedure, with the review rules every lead has to pass, is in docs/AGENT_RUNBOOK.md.

How a run is recorded

Each run records provenance and writes a sky record.

Note

Evidence labels state the strength of the checks. They do not state a confirmed discovery.

The evidence levels describe the evidence. They do not say how exciting a target is:

  • Unverified lead: an observed feature with an unfinished artifact audit.
  • Vetted candidate: it survived every test available.
  • Independently supported: other data back it up.
  • Established: community confirmation.

Pick a target

The normal loop claims the top target of the queue. You can select a different target in three ways:

  • new --from-queue TOI-2423.01 claims a named target from the queue.
  • new --planet "WASP-12 b" builds a campaign for any known planet. Every predicted transit becomes a positive control.
  • new --manual NAME --tic N --ra DEG --dec DEG --t0 BJD --source "..." builds a campaign for anything else.
Note

Do not edit the numbers of a generated specification by hand. If a value is wrong, fix the source and generate the specification again.

python -m cygnus.batch drives the same loop for tens to hundreds of targets. Every campaign it makes is identical to a campaign made by hand.

Run on Colab

The notebooks in notebooks/ run the tiered lead pursuit and the reusable second stage on Google Colab. The index files docs/colab_runs/ and storage/locations.jsonl list the finished runs.

Publish results

Only the files in publish/collections/*.json become public.

  1. Make the collection file in publish/collections/.
  2. Run python -m cygnus.publish check.
  3. Run python -m cygnus.publish build. The site appears in build/.
Caution

Do not edit the templates to add content. The publication boundary is described in docs/PUBLISHING.md.

Rebuild the sky map

The interactive sky explorer is the public site's home page. To rebuild it, run:

python design-system/mockups/build_explorer.py

New catalogue fetches go through fetch_sky_data.py. It records the provenance of each fetch.

Settings

No credentials are needed. MAST, NASA Exoplanet Archive, VizieR, SIMBAD and the other services are public and anonymous. You can set:

  • CYGNUS_SCRATCH sets where light curves and other downloads go. The default is ~/.cache/cygnus/scratch. A TESS sector for one target uses about 2 MB. It is always safe to delete this folder.
  • CYGNUS_LEDGER sets the SQLite provenance ledger. The default is state/ledger.sqlite, which is made on first use. On a machine other than the main workstation, use your own ledger. Name the run IDs in your report, so the runs can be merged later.
  • campaigns/<id>.yaml holds the parameters of one analysis. The steps are ledgered and resumable. Each analysis regenerates the sky_record.json, and the tests fail without it.
  • python -m cygnus.storage where shows how the current machine reaches the shared Drive storage. Every harness gets there its own way.

Build from source

You need Python 3.10 or newer. The hosted runs use 3.12. On Windows, the venv python is .venv\Scripts\python.

git clone https://github.com/mariyaholic/ad_astra && cd ad_astra
python -m venv .venv
.venv/bin/python -m pip install -e ".[test,site,campaign]"
.venv/bin/python -m pytest -q

The science extras are mast, timing, imaging, moving and analysis. Install them if you want more than the campaign runner. The list is in pyproject.toml.

The tests run offline by default. -m network runs the live archive probes.

Bulk archive data, the ledger (state/), scratch downloads and credentials stay out of the repository (.gitignore). The Tier-1 data products live in private cloud storage. This repository holds their manifests and checksums, so every product can be fetched again from its public archive.

Run the tests

Run the test suite from the source checkout: 

.venv/bin/python -m pytest -q

Limits

Warning

Use public or synthetic inputs for examples. Keep personal storage paths and credentials out of reports.
