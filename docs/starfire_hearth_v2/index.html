Starfire Hearth

Starfire Hearth is a turn-based space strategy game. The simulation and the display are separate layers.

Run the first scenario

  1. Open the source in Godot 4.7.2 stable. Import the project once: 
    godot --headless --path . --import
  2. Run the data validator and the tests: 
    godot --headless --path . -s tools/validate_data.gd
godot --headless --path . -s tests/run_tests.gd
  3. Start the game: 
    godot --path .
  4. From the title screen, select Scenario 1. Play through to the debrief.

Explore with the M2A preview

The M2A Exploration Preview is a separate milestone. Launch it from Campaign. It does not complete Scenario 2, and it does not unlock later campaign chapters.

The preview adds civilian interstellar travel, frontier surveys, an outpost and a new colony. Opt a survey probe into automatic exploration, or resolve a one-shot discovery at Halden's dormant gate.

Stop a journey at its next system. Or take an optional detour beyond Vesper to The Shroud's derelict and its energy and research outpost. Surveyed outpost sites show projected production and upkeep before a builder arrives.

After preview victory, choose Continue expedition. It lets you finish optional investments and keeps the original completion date. Later defeat still applies.

Note

Older preview saves keep their original map. Start a new expedition to explore The Shroud.

The plans, the evidence and the platform acceptance limits are in docs/milestones/.

How the game is built

The simulation runs independently of the UI. The game data lives in JSON. The player-facing strings live in strings/en.csv.

Note

Install the matching export templates before you export builds.

Install the requirements

  1. Install Godot 4.7.2-stable, standard build. The file .godot-version pins the exact version.
  2. Install the export templates for 4.7.2 if you want to export builds.
  3. Install xvfb-run on Linux if you run the screenshot tour and no display is available.
Note

The web smoke test needs Node and the playwright npm package with its Chromium. Run npx playwright install chromium to install the browser. If the package is not installed globally, set PLAYWRIGHT_DIR to the node_modules folder that holds it.

Command reference

Run the commands from the repository root. The --import command builds Godot's import cache and the class list. Run it once after you clone, and again after you add new scripts or assets.

CommandWhat it does
godot --headless --path . --importImports the assets and registers the class names.
godot --headless --path . -s tools/validate_data.gdChecks the data schema and the cross-references.
godot --headless --path . -s tests/run_tests.gdRuns the full headless test suite.
godot --headless --path . -s tools/expedition_bot.gd -- --seed 1 --traceRuns the M2A expedition.
godot --headless --path . -s tools/expedition_bot.gd -- --seed 1 --continue --traceContinues the expedition into a later investment.
godot --headless --path . -s tools/expedition_bot.gd -- --seed 1 --route vesper-first --outpost research --traceRuns the optional Shroud itinerary.
godot --headless --path . -s tools/bot_run.gd -- --scenario s1 --policy random-legal --seeds 1-3 --turns 60 --out telemetry/ --check-determinismRuns random legal play and checks that the runs stay deterministic.
godot --headless --path . -s tools/telemetry_report.gd -- --in telemetry/Makes a report from the telemetry files.
godot --headless --path . -s tools/palette_report.gdChecks contrast and colour-blind separation.
xvfb-run -a -s "-screen 0 2560x1600x24" godot --rendering-driver opengl3 --path . -s tools/screenshot_tour.gd -- --out screens/Takes the screenshot tour with no display.
xvfb-run -a -s "-screen 0 2560x1600x24" godot --rendering-driver opengl3 --path . -s tools/icon_sheet.gd -- --out screens/icon_sheet.pngMakes the icon sheet with no display.
mkdir -p build && touch build/.gdignoreKeeps the exports out of the editor's scan.
godot --headless --path . --export-release "Web" build/web/index.htmlExports a web build. "Windows" and "Linux" work too.
node tools/web_smoke.mjs --build build/web --out screens/webTests the web build in headless Chromium.
godot --path .Runs the showcase.
Note

The screenshot tour and the icon sheet need a renderer. On a machine without a display, run them under xvfb-run as the table shows.

Note

Add -- --filter rng to the test command to run only the test files or methods whose name contains rng.

Note

The expedition harness starts with the original automated route. The optional Shroud routes hold Vesper development until the requested outpost is built, so a completion cannot skip the tested investment. Both optional outpost kinds select research cards with the same policy. Add --research-cards to enable that policy on the default route too. These runs are deterministic coverage itineraries. They do not measure optimal play or balanced alternatives.

Find your way around the code

PathWhat lives there
sim/Pure simulation: state, rules, commands, turn processing, RNG, saves. No nodes, no UI.
data/All game content as JSON.
strings/en.csvEvery player-facing string.
ui/Presentation only: theme, components, screens, map renderers.
app/Autoloads: Settings, Strings, Layout, Overlay, Game, SaveService.
assets/SVG icons, fonts (IBM Plex, OFL), audio.
tests/Headless tests: unit, integration, golden, fixtures.
tools/Data validation, bot playthroughs, telemetry, screenshot tour, id audit, icon sheet, web smoke test.
docs/Design log and milestone plans and reports.

The rules of the codebase

  • sim/ never touches Node, SceneTree, Input or ui/. A test scans for it.
  • The simulation state uses integers only. Resources count in hundredths. Percentages count in basis points.
  • The UI never recomputes game math. It shows the Breakdown and ReportItem objects that the simulation emits.
  • The UI holds no raw ids. All text comes from strings/en.csv.
