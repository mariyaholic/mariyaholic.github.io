Uika

Uika is a command-line tool for coding agents. It makes the instruction files, skills and session hand-offs in your repositories from one source. It then checks that the files do not change from that source.

Status
0.1.0 source preview
Runtime
Node.js 22 or later, no npm dependencies
Source
mariyaholic/uika-public, commit 89b46db
License
MIT
Caution

The npm package is not published. Do not use npm i -g uika or npx uika. Run Uika from a source checkout, or from a package file that you make from the source.

Concepts

Estate
The directory that holds your configuration: estate.json, your rules file and your skills. Uika finds it from --root, then from UIKA_ESTATE_HOME, then from the current directory.
Law block
A marked section that Uika writes into the AGENTS.md file of a repository. It has a SHA-256 fingerprint. Do not edit the text between the markers.
Skill
A folder with a SKILL.md file. The source has 39 skills.
Hand-off
A six-line entry in WORKSTACK.md that records what a session did and what to do next.
Note

Configuration files keep the names of environment variables only. They do not keep the values of keys or tokens.

Install from source

  1. Install Node.js 22 or later.
  2. Clone the source repository: 
    git clone https://github.com/mariyaholic/uika-public.git
cd uika-public
  3. Run the machine check: 
    node bin/uika.mjs check
  4. Optional: to put uika on your PATH, make a package file and install it: 
    npm pack
npm install -g ./uika-0.1.0.tgz

Make an estate

  1. Make a new estate: 
    node bin/uika.mjs init my-estate --apply
  2. Check the new estate: 
    cd my-estate
node ../bin/uika.mjs lint
  3. Copy the skills that you need from the skills/ folder of the checkout into my-estate/skills/. The init command does not copy skills.
  4. Validate the skills: 
    node ../bin/uika.mjs skills validate --strict

Write changes

Caution

A command that writes files does a dry run first. It writes only when you add --apply. Read the dry-run output before you add --apply.

Two commands are different:

  • deploy hook-run writes when Git runs it as a post-commit hook. You install this hook with --apply.
  • session check --stop writes a one-byte marker file.

If you use --apply and --dry-run together, the command stops with an error before it does anything.

Verify a checkout

Run these commands from the root of the checkout. All of them must pass.

npm test
npm run scrub
node bin/uika.mjs lint --strict
node bin/uika.mjs docs check --strict

Limits

  • The commands, the estate.json fields and the law-block format can change before version 1.0.
  • Uika does not run a model. The agent tool runs the model and controls access.
  • A test run on Linux does not verify Windows or macOS.
  • Do not put real agent home folders or credentials in examples.
