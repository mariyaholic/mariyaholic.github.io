Uika

Uika is a command-line tool for coding agents. It makes the instruction files, skills and session hand-offs in your repositories from one source. It then checks that the files do not change from that source.

Status
0.1.0 source preview
Runtime
Node.js 22 or later, no npm dependencies
Source
mariyaholic/uika-public, commit 80cbc86
License
MIT
Caution

The npm package is not published. Source publication and an npm release are separate steps. Do not use npm i -g uika or npx uika. Run Uika from a source checkout, or from a package file that you make from the source.

Concepts

Estate
The directory that holds your configuration: estate.json, your rules file and your skills. Uika finds it from --root, then from UIKA_ESTATE_HOME, then from the current directory.
Canonical pair
Two sources are canonical: estate.json (the machine manifest: posture, harnesses, targets, registries) and the estate lawbook. Everything agent-facing downstream is generated from these two.
Law block
A marked section that Uika writes into the AGENTS.md file of a repository. It has a SHA-256 fingerprint. Do not edit the text between the markers.
Skill
A folder with a SKILL.md file. The source has 39 skills.
Hand-off
A six-line entry in WORKSTACK.md that records what a session did and what to do next.
Note

Configuration files keep the names of environment variables only. They do not keep the values of keys or tokens. For example, the manifest contains secretEnv: "GITHUB_MCP_TOKEN", not the token value.

Why an estate layer

Agent harnesses such as Claude Code, Codex, OpenCode, Cline, Gemini CLI, DSH and Hermes run across many repositories. Without an estate layer, each one drifts. Hand-maintained AGENTS.md files go stale. Instructions get pasted between repositories. A skill exists in one harness home but not in another, and nothing tells a session what changed since the last one.

Uika makes the agent-facing layer generated, versioned, fingerprinted and drift-audited instead of hand-copied. The flow is:

estate.json + AGENTS.md (canonical, hand-written)
        │  uika adopt / docs render / deploy
        ▼
law blocks (uika:law:begin … sha256 fingerprint) in every managed repo
skill placement into each harness's skill home
freshness scan + WORKSTACK.md handoff protocol at session start/end

Uika writes the law block in a marked, versioned block:

<!-- uika:law:begin -->
## Estate law (generated — do not edit inside the markers)
...
<!-- uika:generated from estate.json; edit the source, not this file -->
<!-- uika:docs v1 · sha256:54b31598afc2 -->
<!-- uika:law:end -->

uika docs check audits drift. uika lint warns when an always-loaded file passes its budget (200 lines or 32 KiB per harness cap), or when a block goes stale.

Install from source

  1. Install Node.js 22 or later.
  2. Clone the source repository: 
    git clone https://github.com/mariyaholic/uika-public.git
cd uika-public
  3. Run the machine check: 
    node bin/uika.mjs check
  4. Optional: to put uika on your PATH, make a package file and install it: 
    npm pack
npm install -g ./uika-0.1.0.tgz

Choose the estate root

Uika runs against an estate directory. The order is: --root <dir>, then UIKA_ESTATE_HOME, then the current directory.

# A: the tool lives inside the estate (monorepo pattern): the checkout IS the estate root
node bin/uika.mjs lint

# B: the CLI against a separate estate directory (public tool / private estate)
UIKA_ESTATE_HOME=~/estate node bin/uika.mjs docs version
# or: node bin/uika.mjs docs version --root ~/estate

The tool carries zero personal data. Your estate is your own directory: your registries, targets and archives. The source holds synthetic starting points in examples/.

Check what you need

  • Node.js 22 or later. Uika has zero npm runtime dependencies. It uses Node built-ins only.
  • The included CI workflow targets Node 22 on Linux, Windows and macOS. Run npm test for the revision you use and check its CI results. A Linux test run alone does not verify native Windows or macOS behavior.
  • Optional media tools, provider setup and live harness integrations need separate checks in your environment.
  • No archive tool is needed. Version 0.1.0 does not pack skills into zips. The Windows-only skills pack leg was removed (see the manual, part 6).

Make an estate

  1. Make a new estate: 
    node bin/uika.mjs init my-estate --apply
  2. Check the new estate: 
    cd my-estate
node ../bin/uika.mjs lint
  3. Copy the skills that you need from the skills/ folder of the checkout into my-estate/skills/. The init command does not copy skills.
  4. Validate the skills: 
    node ../bin/uika.mjs skills validate --strict

The bootstrap creates an estate scaffold. Its ledger starts unclaimed, and it does not copy the bundled skills into your estate. Read the bundled skills/ from the checkout or installed package, then choose the skills to copy into your estate's skills/ directory. Record your real harness handoff in WORKSTACK.md before you treat a session as complete.

For example, from the checkout, this is the small operating set for a new estate:

node -e "const fs = require('node:fs'); for (const name of ['freshness-scan', 'handoff-protocol', 'principle-prove-it-works', 'wrap-checklist']) fs.cpSync('skills/' + name, 'my-estate/skills/' + name, {recursive: true, force: false, errorOnExist: true});"
node bin/uika.mjs skills validate --root my-estate --strict

The copy refuses existing destinations, so local skill edits are preserved. For a tarball installation, use its packaged skills/ folder as the source. Strict validation fails if no skills were discovered. Ordinary validation reports the empty library explicitly.

Write changes

Caution

A command that writes files does a dry run first. It writes only when you add --apply. Read the dry-run output before you add --apply.

Two commands are different:

  • deploy hook-run writes when Git runs it as a post-commit hook. You install this hook with --apply.
  • session check --stop writes a one-byte marker file.

If you use --apply and --dry-run together, the command stops with an error before it does anything.

Commands that write files (video sheet|frame|structure --out, figure render, eval run) are also dry runs until you pass --apply.

Keep a session honest

Uika defines a session protocol, not folklore:

  1. At the start, run a freshness scan. It lists files by modification time, newest first. Ask the estate if the files matter before you explore further.
  2. Read WORKSTACK.md in the repository root, if it is present.
  3. At the end, run the wrap checklist. It runs the checks, updates the ledger and stops.
  4. Record the handoff in WORKSTACK.md as a six-line entry: from, to, done, next, files, verify, blockers.

uika session check enforces this protocol.

Note

session check --stop records a one-byte, once-per-session sentinel. It goes inside an existing .git/ directory, or the OS temp directory. A Stop hook then blocks at most once per session.

More detail on the media and data commands:

  • video needs ffmpeg and ffprobe on PATH, or UIKA_FFMPEG and UIKA_FFPROBE, for everything except ls, diff and prompt lint.
  • figure renders with guards and a provenance manifest. PNG and PDF output needs Playwright, which is not bundled.
  • ref hash <id> --json prints a read-only baseline for review.
  • eval reads tasks from labs/eval/tasks/*.json. No model API is called by uika.
  • docs migrate [repo] [--apply] repairs legacy repositories. It strips pasted law, folds a hand-written CLAUDE.md into AGENTS.md and keeps .bak-<date> backups.

The dispatcher registers 19 commands. Not bundled (see the roadmap): usage tracker, MCP/model/prompt registries, supply layer, creative ledger/deck/divergence commands, backup, limiter, mt5. For the full list, see the manual.

Use the skills library

skills/ contains 39 estate-authored skills in the Agent Skills format: one folder, one SKILL.md. Seventeen are the original operating and principle skills. Twenty-two are ports that cover creative work, media, figures, evaluation and workflow templates.

Third-party skills are not vendored. See NOTICE and the skills scope and provenance audit.

Six ports are templates with MANUAL.md setup guides. Media kits and raster export need optional tools that the CLI package does not install. Read each skill's requirements before you run its helpers.

To copy your estate's selected skills into its configured harness skill homes, run uika skills place --apply.

Verify a checkout

Run these commands from the root of the checkout. All of them must pass.

npm test
npm run scrub
node bin/uika.mjs lint --strict
node bin/uika.mjs docs check --strict

The test suite includes package-content checks and an isolated tarball install.

Limits

  • The commands, the estate.json fields, the law-block format and the harness mappings can change before version 1.0.
  • Version 0.1.0 is a developer preview. Uika supplies the estate, the skills and the session layer. The harness provides model execution, tool access and its own authorization controls.
  • Uika does not run a model. The agent tool runs the model and controls access. Provider setup and live harness integrations need separate verification.
  • A test run on Linux does not verify Windows or macOS.
  • Do not put real agent home folders or credentials in examples.
