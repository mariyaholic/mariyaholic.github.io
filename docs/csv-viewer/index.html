CSV Viewer

CSV Viewer opens CSV files read-only. It shows rows in pages, a literal search and a scan coverage report.

Platform
Windows x64 for the desktop app and Explorer; Linux and macOS for the terminal pipeline
Runtime
Rust 1.85 or later
Status
0.1.0 source preview, no release
Source
mariyaholic/csv-viewer, commit 012f28d
License
Apache-2.0

Open a CSV file

  1. Build the source (see Build from source).
  2. Render a disposable CSV file with the command-line tool: 
    cargo run -p csv-viewer -- --render path/to/file.csv
  3. For the desktop app, package the app for Windows separately (see the commands below).
  4. Use a disposable file when you examine the desktop app and its Find command.

Search and read the scan coverage

In the desktop app, move through the table by page. Select Find for a literal search.

Note

A limited scan checks only the reported range. When Find shows no match, this does not prove that the whole file has no match. An explicit full scan checks the whole file.

Caution

The table can show a shortened value. If you copy a shortened display value, the clipboard may miss the full original.

The first preview keeps a bounded head of 256 KiB. You ask for the full scan yourself. In the preview window, push the F key. In the terminal viewer, use --full or push the f key.

The report is honest about coverage. A partial scan reports the scanned records, the bytes read and an incomplete reason. It never reports an exact total. Only a complete scan sets total_records.

A date range appears only when you ask for it. You give a 1-based column number and an explicit interpretation: ymd, dmy or mdy. The range appears only after a complete scan (see Use the terminal viewer).

Read the review notes

The viewer writes review notes, not conversions. The source cells stay unchanged. The notes flag leading zeros, ambiguous day/month dates, mixed types, boolean spellings, long numbers, formula-like text, link-like text, quoted multiline fields, ragged rows, duplicate header names and replacement errors. Each note carries bounded samples and counts.

Use the desktop app

A native Windows desktop companion exists as a portable developer ZIP. Extract the ZIP and run csv-desktop.exe. No COM registration is needed.

The app is a bounded, read-only paged browser. It has cross-page literal search. It is not an editable spreadsheet.

The app ships six themes: Paper, Ink, PC-98, Doloris, Sumimi and Marigold.

The large-file guide gives the browsing and search limits. The standalone usage guide gives the run and build instructions, the limits and the remaining native acceptance. The six-theme design system defines the themes and the component contracts for future features.

Detect the encoding and dialect

The viewer detects the encoding and the dialect before it shows rows.

  • Encodings: UTF-8, UTF-16LE, UTF-16BE and Windows-1252.
  • Delimiters: comma, semicolon, tab and pipe.
  • Quoted fields and embedded newlines are read as one field.

You can override each choice on the command line:

cargo run -p csv-viewer -- --render --delimiter ';' --encoding windows-1252 \
  --header present path/to/file.csv

Use the Explorer preview

The Explorer preview handler is an opt-in Windows feature. The handler reads the stream that Explorer supplies. It never assumes a filesystem path. It renders a text preview with the source cells unchanged. It supports IInitializeWithStream and IPreviewHandler.

Registration is per-user, under HKCU\Software\Classes and HKCU\Software\Microsoft\Windows\CurrentVersion\PreviewHandlers.

Note

Registration warns before it changes a preview association. It removes only registry values that still point to this handler. Shared registry keys are never deleted. Empty keys are expected residue. The handler's exclusive CLSID tree could be deleted safely, but it is also left in place.

The DLL, the worker and the COM implementation live in crates/csv-preview behind cfg(windows). They need a 64-bit Windows build and real Explorer testing. Read the testing notes before you distribute the handler. The status document gives the current state.

The worker process

A separate csv-worker process reads the file. The host passes a path inside a private spool directory and an exact byte count. The protocol is versioned and length-prefixed, with a bounded frame size. Worker and request limits cap records, bytes and time.

Read market heuristics

The market heuristics are optional and off until you map the OHLC fields yourself. The viewer can then report a constant spread, an open equal to the previous close, return tails, price plausibility and missing data. Thresholds and sample sizes bound each report.

Note

Baseline comparison is unavailable unless you supply a dated, licensed, instrument-specific local baseline.

The viewer writes nothing and calls no trading interface. A future market-data reader would be strictly read-only: no order placement, modification, closing or other trading calls.

Note

The market findings are heuristics. They are not proof of fraud or authenticity and not financial advice.

MT5/MetaTrader integration is not included. CSV viewer and preview is not affiliated with MetaQuotes; MT5 is a MetaQuotes trademark.

Use the terminal viewer

The csv-viewer companion is a small cross-platform terminal viewer with a virtualized table, review notes, scan details and an About screen. The plain-text render is used automatically when stdout is not a terminal.

# Plain-text preview
cargo run -p csv-viewer -- --render path/to/file.csv

# Interactive viewer
cargo run -p csv-viewer -- path/to/file.csv

In the interactive viewer, the arrow keys scroll, PgUp and PgDn move by page, w shows warnings, d shows details, a shows About, f runs an explicit full scan and q quits.

A complete scan with an explicit date range uses a 1-based column number:

cargo run -p csv-viewer -- --render --full \
  --date-column 1 --date-format ymd path/to/file.csv

The settings file

Settings are a JSON file per user. On Windows, the file is %APPDATA%\csv-viewer\settings.json. On other systems, it is $XDG_CONFIG_HOME/csv-viewer/settings.json or ~/.config/csv-viewer/settings.json.

  • CSV_VIEWER_SETTINGS and --settings select an explicit file.
  • CSV_VIEWER_WORKER overrides the worker path that embedders use. The COM handler looks for csv-worker.exe next to the DLL.

Settings hold dialect overrides, the preview size and an optional market field mapping. They never contain credentials. Do not put any in them.

Note

These terminal and preview settings are separate from the desktop appearance preferences.

Build from source

To package for Windows x64 from a Unix-like host, install the Rust Windows GNU target, a MinGW-w64 cross compiler and linker, Python 3, zip and sha256sum first. Fetch the locked dependencies before you run the offline build script.

cargo build --workspace --locked
cargo test --workspace --locked
cargo run -p csv-viewer -- --render path/to/file.csv
rustup target add x86_64-pc-windows-gnu
cargo fetch --locked --target x86_64-pc-windows-gnu
bash scripts/build-desktop.sh --debug

The build needs Rust 1.85. No Windows target or cross-compiler is needed for the Linux build; the Windows module is excluded.

To type-check the Windows-only module on a non-Windows host, with no link and no run:

RUSTFLAGS='--cfg csvview_windows_check' cargo check -p csv-preview

Build for Windows

Run scripts/build-windows.ps1 on Windows with the x64 MSVC Rust target. Run scripts/build-windows.sh on Linux with the x64 GNU target and MinGW. Both produce the viewer, the worker, the DLL and SHA256SUMS in dist/. Set DIST_DIR to choose another output directory for the shell script.

Both scripts use the last commit timestamp for SOURCE_DATE_EPOCH and remap the source paths. To verify reproducibility, use the same toolchain, dependencies, source and environment.

Limits

Note

No public release exists. Keep the worker executable, fonts, help and licences next to the desktop executable in a portable folder. Explorer registration stays optional.

  • Preview head: 256 KiB, 200 rows by default. The preview cell text is capped at 1 MiB per report, so the worker frame stays bounded.
  • Full scan: 100,000,000 records, 4 GiB source and 120 s by default. Fields are capped at 4,096 display characters and columns at 1,024. A reached limit makes the result partial.
  • Spool: a private temporary directory with a 4 GiB cap. If the source is larger, the spool is truncated and the scans are partial. The source itself is untouched.
  • Partial byte coverage is estimated at record boundaries. For multi-byte encodings, it is interpolated, not an exact byte count. Record counts are exact for the records parsed. A complete scan has an exact byte total.
  • The source is opened read-only. Labels are treated as text: formulas are never evaluated and links are never opened.
  • No network access, no telemetry, no uploads. Network use is not required at runtime.

Release status

The first planned public beta is the standalone Windows x64 desktop only. No public release is available yet.
