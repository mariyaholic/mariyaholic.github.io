Draft module

Show what happens next.

Use a small state flow to explain how something works. Keep the labels generic so it shows the shape, not the private details.

Input hits a guard, the guard picks a state, and the state leaves a receipt. Rejected paths go in the picture too.

Tried and rejected: Every lineage has a context file that first records what was already tried and rejected. Bringing back a rejected idea without new evidence is the most common mistake here.

Input

An event, order, request, or saved state enters the system.

Guard

A named constraint accepts, holds, or rejects the next step.

State

The reducer records the resulting state and the reason it changed.

Receipt

The method, status and limits show up next to the claim.

The trace

A state trace you can follow.

Same shape as a deterministic game turn, an ingestion guard, or a research receipt. The values are made up. The interaction is real.

Status labels

Each step carries its status.

Four labels: fixture, local, review and open. None of them means live or released.

Fixturerepeatable example with known inputs
Locala check in one stated mode
Reviewsomeone else reads the receipt
Openthe next check is written down

Ten turns, three states

Synthetic demonstration - not a measured result. A made-up trace goes from ready to held to accepted. It shows how to follow a guard. It says nothing about markets or a real save.
